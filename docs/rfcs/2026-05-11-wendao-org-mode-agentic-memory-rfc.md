# Org-Mode as the Agentic Memory and Reasoning Format

## 1. Vision and Motivation

In advanced Agentic workflows (like the Strategy Flow and BPMN Deduction Loop), agents must maintain a "Reasoning Trace" (memory) across multiple turns.

- **The Markdown Failure**: Markdown is a presentation language. It lacks formal syntax for state machines, metadata attachment, and rigorous table structures, leading to brittle parsing.
- **The JSON Failure**: While structured, JSON is hostile to human auditing, consumes excess tokens for formatting, and LLMs frequently generate malformed JSON (e.g., missing brackets) when generating long, complex reasoning chains.

This RFC establishes **Org-mode** as the canonical intermediate representation (IR) for LLM reasoning and system memory in `xiuxian-artisan-workshop`.

## 2. The Superiority of Org-Mode for AI Agents

Org-mode, refined over decades in the Emacs ecosystem, is a heavily structured, tree-based database disguised as plain text. LLMs possess deep, pre-trained fluency in Org syntax due to its prevalence in open-source datasets.

Its syntax provides native, robust primitives critical for Agentic reasoning:

- **Strict Hierarchies**: Deterministic tree structures via `*`, `**`, `***`.
- **State Machines**: Native `TODO`, `DOING`, `DONE` keywords, perfectly aligning with our BPMN node states.
- **Property Drawers**: `:PROPERTIES:` blocks allow the injection of hidden, strongly-typed metadata (e.g., `Confidence: 0.95`, `Source_URI: ...`) without breaking the human-readable flow.
- **Rigorous Tables**: Org-tables have strict column alignments and formulas, making them vastly superior to Markdown tables for data extraction.

## 3. The `orgize` Integration: Semantic AST as a Database

The architecture does not merely use the `tao3k/orgize` crate as a text parser; it utilizes it as a **Semantic Projection Engine**. A deep architectural review of the `orgize` codebase (specifically `semantic_ast/model.rs`) reveals its true power: it projects flat text into a strongly-typed, relational-database-ready structure.

### 3.1 The Agentic Memory Loop via Semantic AST

1.  **Generation**: The LLM outputs its deductive reasoning, extraction results, or strategy plan strictly in Org-mode format.
2.  **Native Semantic Extraction**: The `orgize` crate parses this text, generating a `ParsedAst` (`Document<ParsedAnnotation>`). Unlike generic parsers, `orgize` explicitly models complex structures as Rust types:
    - `Section`: Natively holds `properties: Vec<Property>`, `todo: Option<TodoKeyword>`, `tags`, and `planning` (deadlines/schedules).
    - `Table`: Accurately resolves `is_rule` separators, `column_alignments`, and cells.
3.  **Zero-Copy Projection**: Because the `orgize` AST strictly types `Properties` and `Tables`, the Rust orchestrator does not need to "extract" data; it directly projects these Rust structs into **Arrow IPC RecordBatches** or **DuckDB Tables** via memory mapping.
4.  **Absolute Provenance**: Every `Element` and `Section` generated by `orgize` contains a `ParsedAnnotation` containing exact `TextRange` and `SourcePosition` (Line/Column). If an Agent hallucinates invalid syntax, the system throws a deterministic error pointing to the exact character in the LLM's output stream, enabling autonomous self-correction.

## 4. Architectural Impact

By utilizing Org-mode and the `orgize` parser, we achieve a profound architectural harmony:

- **Human-Machine Duality**: The reasoning traces remain highly readable plain text for developers reviewing logs, yet they execute as a strict, high-performance database for the Rust backend.
- **Latency Collapse**: Eliminates the need for brittle regex parsing or slow Python-based data extraction. `orgize` provides native semantic extraction at the speed of memory.
- **Self-Healing**: If an Agent's reasoning drift occurs, the structural rigidity of Org-mode (e.g., a missing `:END:` tag) fails cleanly at the Rust parser level, triggering an immediate, deterministic self-correction loop before bad data pollutes the Knowledge Graph.

## 5. Conclusion

Transitioning from Markdown to Org-mode as the primary serialization format for Agent reasoning resolves the fundamental tension between unstructured LLM outputs and the strict data requirements of the Semantic Ontology Engine. Coupled with the native `orgize` parser, it enables the `xiuxian-artisan-workshop` to maintain complex, multi-turn cognitive states with absolute structural integrity and near-zero latency overhead.
