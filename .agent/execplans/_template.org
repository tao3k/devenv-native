*** RTK Project Command Guide

- Rust focused checks: =direnv exec . rtk --ultra-compact cargo test -p <crate> <filter> --lib=.
- Rust compile/lint gates: =direnv exec . rtk --ultra-compact cargo check -p <crate>= and =direnv exec . rtk --ultra-compact cargo clippy --all-targets --all-features -- -D warnings=.
- TypeScript/package checks: =direnv exec . rtk --ultra-compact npm run check=, =direnv exec . rtk --ultra-compact npm run build=, or the package-specific =npm run <script>=.
- Python checks: =direnv exec . rtk --ultra-compact pytest -q= and =direnv exec . rtk --ultra-compact ruff check <path>= when the wrapper applies.
- Git and small inspections outside the project environment: =rtk git status --short=, =rtk git diff -- <paths>=, =rtk read <path>=, and =rtk ls <path>=.
- Search policy: prefer raw =rg= for fast repository search; use RTK wrappers only when they provide useful filtering for the command being run.
- Org recovery and lint: use the installed =wendao-client= directly. Prefer =wendao-client orgize task-probe --cached --text '<remembered text>' <path>= when the agent has memory, =wendao-client orgize ogrid-show --cached --id <org-section-id> <path>= when it knows the section ID, and =wendao-client orgize task-recover --cached <path>= only when it has no useful memory.
- Julia, artifact-producing, parser-output, or exact-transcript commands: use raw =direnv exec .= unless =rtk rewrite <command>= shows a real filtered wrapper.
