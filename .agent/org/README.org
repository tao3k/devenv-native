* Agent Org Workflow
This file defines the repository-local Org workflow for agent task tracking.
It uses task-local Org headings, native time markers, and command-line recovery
queries.

** Tracking Surfaces

Use SDD plus task surfaces:

1. SDD: durable system/capability/view/decision/audit direction under =$PRJ_CACHE_HOME/agent/sdd/=.
2. ExecPlan: optional detailed execution log under =$PRJ_CACHE_HOME/agent/execplans/=.
3. Org task ledger: current task state under =$PRJ_CACHE_HOME/agent/org/=.

The Org task ledger owns task lifecycle state, schedule markers, recovery
queries, and evidence pointers. The SDD owns architecture description, design
rationale, audit concerns, and parent/child design edges. The ExecPlan owns
detailed execution logs when a slice needs them. Package docs own durable
public behavior.

** Task Lifecycle

Use native Org state and time markers:

1. =TODO= means the plan exists and is ready or resumable.
2. =DOING= means an agent has actively started executing that task.
3. =DONE= means the slice is validated and no longer belongs in the active
   recovery view.
4. Active timestamps such as =<2026-05-23 Sat>= may be placed directly in the
   task heading when they are part of the visible recovery anchor. Inactive
   timestamps such as =[2026-05-23 Sat]= are historical/archive evidence.
5. =SCHEDULED:= records the next planned work date.
6. =DEADLINE:= is optional and only for real calendar pressure.
7. =CLOSED:= records completion time with an inactive timestamp, for example
   =CLOSED: [2026-05-24 Sun]=. Do not use active =<...>= timestamps for
   closure.
8. Progress cookies such as =[1/3]= and =[33%]= belong on task headings that
   contain direct checkbox checklists, direct TODO/DONE child headings, or both.
9. Checkbox items use native Org states: =- [ ]= for open work and =- [X]=
   for completed work.
10. If a heading has both TODO children and checkboxes, set
   =:COOKIE_DATA: direct= in the property drawer so Orgize counts only the
   current heading's direct checklist items and direct TODO/DONE child headings.
11. Do not leave empty property values in templates. Omit optional fields that
   do not apply, or use =none= only when an explicit negative value is useful
   for recovery.
12. Repeated agent tasks use native Org repeater cookies on =SCHEDULED:= or
    =DEADLINE:= timestamps, for example =<2026-05-18 Mon ++1d>= for a cadence
    that catches up to the next future occurrence and =<2026-05-18 Mon .+1w>=
    for a cadence measured from completion time.
13. When a task needs both =SCHEDULED:= and =DEADLINE:= metadata, keep them on
    the same planning line so the Orgize read model preserves both timestamps.

A task's heading is the durable recovery anchor.
Create new planned work as =TODO=. When an agent starts implementing that
specific task, change the heading keyword to =DOING=. After validation and
evidence are recorded, change it to =DONE= and add =CLOSED: [YYYY-MM-DD Day]=.

** Command Discipline

Agent shell commands MUST follow the repository RTK policy. New Org task
headings should keep =:COMMAND_POLICY: RTK.md= in their property drawer so
command evidence remains aligned with the repository RTK contract.

** Recovery Commands

Recover active work without reading chat history first:

#+begin_src text
rtk wendao-client orgize task-list --cached $PRJ_CACHE_HOME/agent/org
#+end_src

Recover a small reasoning-tree candidate window from recently modified Org
task files:

#+begin_src text
rtk wendao-client orgize task-recover --cached $PRJ_CACHE_HOME/agent/org
#+end_src

Refresh the authoritative DuckDB read model after editing Org files or when a
cached query looks stale:

#+begin_src text
rtk wendao-client orgize task-list $PRJ_CACHE_HOME/agent/org
#+end_src

Recover SDD system/capability/view/decision/audit status:

#+begin_src text
rtk wendao-client orgize sdd status $PRJ_CACHE_HOME/agent/sdd
#+end_src

The task-list command excludes DONE and archived rows by default and renders
native Org repeater cookies as =repeat:= metadata. Use =--cached= for fast
turn-start recovery from the current DuckDB snapshot; omit it when the query
must refresh from Org source files first. Add =--output json= or =--output
pretty= when automation needs limited task rows, next actions, resume queries,
and repeater metadata as a machine-readable recovery contract.

Each agent task row is identified by the Org section =:ID:= property and renders
that value as =orgid:=. Use =ogrid-show= when a resumed session already knows the
current section ID and needs the exact subtree instead of a broad SDD or task
directory scan:

#+begin_src text
rtk wendao-client orgize ogrid-show --cached --id <org-section-id> $PRJ_CACHE_HOME/agent/org
#+end_src

When the resumed agent remembers the task title or lane phrase, use that memory
as the first query. =task-probe --text= is the low-token remembered-task probe:
it builds a temporary memory window from Org syntax facets such as heading
lifecycle, planning timestamps, tags, property drawers, SDD graph references,
linked SDD metadata/headings, progress cookies, and checklist next actions. The
probe uses =xiuxian-memory-engine= reranking plus structured Org facet fusion,
so multi-facet agreement can outrank a noisy title-only phrase match. It
defaults to three compact candidate rows and renders =checklist-progress:=,
=next-unchecked:=, and a =show:= command for exact checklist recovery:

#+begin_src bash
rtk wendao-client orgize task-probe --cached --text '<remembered task title>' $PRJ_CACHE_HOME/agent/org
#+end_src

Use =task-list --text= only when the agent needs richer row metadata for the
matching candidates before choosing an =orgid=.

When the resumed agent does not remember the task title, use recent modified
recovery first. =task-recover= returns the most recently modified active
candidate rows and prints =file-key=, =query-file=, =query-title=, and =show=
commands so the agent can narrow from recent files to one task without dumping
whole Org subtrees:

#+begin_src text
rtk wendao-client orgize task-recover --cached $PRJ_CACHE_HOME/agent/org
#+end_src

Find scheduled work for one day or a date window:

#+begin_src text
rtk wendao-client orgize agent-planning --date YYYY-MM-DD $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize agent-planning --date YYYY-MM-DD --end YYYY-MM-DD $PRJ_CACHE_HOME/agent/org
#+end_src

Find one lane by stable text:

#+begin_src text
rtk wendao-client orgize task-list --cached --text '<lane-or-package>' $PRJ_CACHE_HOME/agent/org
#+end_src

Open a named DuckDB-backed control view:

#+begin_src text
rtk wendao-client orgize task-list --cached --view closure-needed $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-list --cached --view archive-candidate $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-list --cached --view achievement $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-list --cached --view repeating $PRJ_CACHE_HOME/agent/org
#+end_src

Review completed achievement task rows without polluting active recovery:

#+begin_src text
rtk wendao-client orgize task-list --cached --view achievement $PRJ_CACHE_HOME/agent/org
#+end_src

Summarize archive candidates, achievements, repeaters, and tag counts:

#+begin_src text
rtk wendao-client orgize task-report --cached --summary-only $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-report --cached --view archive-candidate $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-report --cached --view closure-needed $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-report --cached --view repeating $PRJ_CACHE_HOME/agent/org
#+end_src

Omit =--cached= from =task-report= when the summary must refresh the read model
before rendering. Omit =--summary-only= when the report should include detailed
task rows for each section. Add =--output json= or =--output pretty= when a
script or agent needs the report counters, tag counts, and section counts as a
machine-readable summary contract.

Plan physical archival for completed task rows:

#+begin_src text
rtk wendao-client orgize task-archive $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-archive --closed-before YYYY-MM-DD $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-archive --closed-before YYYY-MM-DD --expect-selected COUNT $PRJ_CACHE_HOME/agent/org
#+end_src

Apply a reviewed archive plan explicitly:

#+begin_src text
rtk wendao-client orgize task-archive --apply $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-archive --apply --closed-before YYYY-MM-DD $PRJ_CACHE_HOME/agent/org
rtk wendao-client orgize task-archive --apply --closed-before YYYY-MM-DD --expect-selected COUNT $PRJ_CACHE_HOME/agent/org
#+end_src

The archive command prints an =Archive Targets= summary before row details so
operators can review the write targets and selected row counts before applying
the plan. By default, each archived task moves to
=$PRJ_CACHE_HOME/agent/org/archives/<source-task-file>.org=. Do not archive
into year buckets such as =2026.org=; those become noisy aggregate ledgers.
After =--apply=, the command prints a compact write receipt with updated source
and target counts, then refreshes the DuckDB read model so subsequent
=--cached= recovery sees the post-archive state. Use =--closed-before= to keep
newly completed same-day tasks out of a bulk archive run. Use =--expect-selected=
after reviewing a plan so an apply fails before any write when the selected row
count changes. Add =--output json= or =--output pretty= in plan mode when
automation needs selected rows and archive target counts as a machine-readable
review contract. The same output flags in apply mode emit a write receipt with
updated source/target paths and post-apply read-model counters.

Use sparse-tree when the full source subtree context is useful:

#+begin_src text
rtk wendao-client orgize sparse-tree --match '+agent+achievement' $PRJ_CACHE_HOME/agent/org
#+end_src

Lint SDD and task tracking files before marking a tracking slice complete:

#+begin_src text
rtk wendao-client orgize lint --format compact $PRJ_CACHE_HOME/agent/sdd
rtk wendao-client orgize lint --format compact $PRJ_CACHE_HOME/agent/org
#+end_src

Define repeated performance/profile checks with native Org timestamps:

#+begin_src org
* TODO Wendao Performance Profile Cadence <2026-05-18 Mon> [0/5] [0%] :agent:performance:
SCHEDULED: <2026-05-18 Mon ++1d>
:PROPERTIES:
:COOKIE_DATA: direct
:NEXT_ACTION: Refresh the benchmark baseline and compare the current candidate.
:COMMAND_POLICY: RTK.md
:END:

- [ ] Refresh the frozen baseline before judging a candidate.
- [ ] Run the current candidate profile with a stable harness command.
- [ ] Compare latency, row count, ordering, and precision gates.
- [ ] Record evidence in the active ExecPlan or package docs.
- [ ] Decide whether to continue optimizing, archive the slice, or open the next one.
#+end_src

The stable client-side Org read-model benchmark is:

#+begin_src text
rtk cargo bench -p xiuxian-wendao-client --features performance --bench wendao_client_orgize
#+end_src

The benchmark fixture covers 1,024 agent task rows and measures refresh through
DuckDB materialization plus cached query. Use it when changing Org tracking
read-model storage, archive planning, or recovery query behavior. The current
local profile is roughly 42-57 ms for refresh plus cached query, and roughly
6.1-6.8 ms for the cached active recovery window with a limit of 20 rows.

** Completion Protocol

When a slice is complete:

1. Mark the task heading =DONE=.
2. Add a =CLOSED:= timestamp.
3. Record exact evidence in =EVIDENCE= and the task's =** Evidence= section.
4. Complete the task's =** Closure Questions= table. The table may contain any
   number of question rows; every row with a non-empty =Question= cell must have
   a non-empty =Value= answer cell.
5. Update the paired SDD audit or evidence note when the architecture contract
   changed.
6. If the task used an ExecPlan, update its outcome and move it to
   =$PRJ_CACHE_HOME/agent/execplans/archives/=.
7. Keep the task heading in the ledger only if it is needed as a lane index;
   otherwise move the completed subtree to the configured archive target.

The active recovery query excludes DONE headings by default, so completed
headings do not block the next agent turn even before physical archival.

** Resume Protocol

At the start of a resumed turn:

1. Run =task-probe= when the remembered title or file key is available.
2. Run =ogrid-show --id= when the remembered Org section ID is available.
3. Use =task-recover= only when the session has no useful task memory.
4. Read the top-level progress cookie and the next unchecked checklist item.
5. Read the paired SDD or optional ExecPlan only after the task-local checklist
   identifies that broader context is needed.
6. Continue from the next unchecked checkpoint.

This protocol complements the agent turn loop. The chat resume gives recent
conversation state; the Org ledger gives durable task state.

** Archive Discipline

Archive only completed, validated slices. Do not archive active or blocked
tasks.

Archive targets are raw subtree sinks named after the task source file. Do not
add =#+TITLE=, =#+AUTHOR=, =#+DATE=, or =#+FILETAGS= headers to archive target
files; the archived subtree already carries its lifecycle state, inactive
=CLOSED:= timestamp, =ARCHIVE= tag, evidence, and answered closure table.

Archived tasks may remain queryable by omitting sparse-tree =--exclude-archived=
and =--exclude-done= filters. They should not appear in active task-list
recovery unless =--include-archived= or =--include-done= is explicitly set.
